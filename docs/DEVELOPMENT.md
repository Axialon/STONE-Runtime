# Scoped native development and independent acceptance

The supervising conversation chooses an approved technical task and accepts the result. A single repository-native Codex writer owns a dedicated source checkout, with normal workspace-write sandboxing and a clean child environment. Explicitly set the working directory in commands and verify it; do not assume the requested root reached the native shell. Use exact task session IDs when resuming, never a global last-session selector that could select a sibling project.

Give the writer a bounded deliverable, relevant files, fixed invariants, baseline revision and acceptance commands. It reads and edits its own source, observes narrow failures and repairs them locally. A separate read-only reviewer inspects actual code and requirements. The supervisor owns the integration checkout, source transfer, complete product acceptance, PRs and component pin. Only one writer owns each source scope. No unattended loops or implementation daemons.

Do not weaken sandboxing to make Git or browser tools work. In the tested setup native source edits and direct Node tests work, but the agent sandbox protects .git and has subprocess/physics/browser limitations. Git commits and full acceptance therefore stay with the supervisor. An exit code or file-level test summary is not proof that all product cases ran. Preserve failed attempts and report actual scope rather than trusting a model summary.

The full product gate is the existing `npm run verify:full`, after the pinned inference bundle is built. Run it from an exact clean source snapshot with reviewed dependencies, lifecycle scripts disabled and the established reduced-privilege browser environment. Compare source hashes, review the result and integrate only that tree. Refresh the preview from an immutable accepted snapshot, not the writer's unfinished branch.

Task selection and integration status belong to the coordinator's one execution board; supplied task briefs are snapshots, not a second queue. Issues carry discussion and evidence links. The private project pin must match the stated accepted runtime or explicitly record an integration-pending state. Keep current memory compact; previous states live in Git/evidence rather than accumulating in current instructions. No private queue, credentials, machine home paths or raw agent transcripts belong in this public component.

No extra model API purchase, account/trust change, public app deployment, new collaborator, physical actuation or sibling-project modification is implicit in development. Source/model licences and model-vs-harness limits remain explicit. This workflow was exercised during portable Stone acceptance; no numeric speedup or cost saving is claimed without comparable measurements.
