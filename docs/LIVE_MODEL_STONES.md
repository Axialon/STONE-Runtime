# Live model-backed Stones

FLOW / Learned can now run in the existing Rover workbench, not just the offline experiment. Its saved CART artifact is unchanged. This is local longitudinal imitation with explicit deterministic steering/guards, restricted to the two fixed lanes. The three original rule packages, custom routes and all-host navigation remain available.

## Prepare and run
From the repository root, after the normal Rapier/browser installation:

```sh
npm --prefix experiments/learned-flow ci --ignore-scripts --no-audit --no-fund
npm --prefix tools/model-bundle ci --ignore-scripts --no-audit --no-fund
npm run build:models
npm start
```

The two extra package sets can be installed offline when already cached. Model fitting is not part of this startup. The build uses pinned esbuild-wasm0.28.2 and the installed ml-cart2.1.1, writes a local ESM bundle plus input hashes and complete upstream notices, and needs no runtime CDN. Generated files are ignored rather than committed as unexplained vendor binaries. Missing optional dependencies/build leave default rule use intact; model mode reports an explicit failure, never a hidden fallback. `npm run verify:model-build` rebuilds and verifies the generated bytes.

Open the Rover section and enable **Explore a learned Stone**. The checkbox explicitly resets the run and selects FLOW / L. Start, pause, step or swap between the four compatible packages. Subsequent swaps retain position, orientation, momentum and time. The interface shows the last applied decision source (MODEL, GUARD with reason, or RULE), actual inference count, model identity and accurate supporting-code description. A selected model does not imply every tick used inference: airborne/goal/out-of-domain handling is labelled GUARD.

**Compare all four** runs the same fixed machine/course. Reports include model calls and complete implementation identities. Browser results match Node on both fixed lanes. These are reference scenarios, not a new held-out experiment or superiority claim. The actual learned model only controls acceleration/braking, not steering, obstacle avoidance, general navigation or hardware.

## Route Studio boundary
Custom checkpoint editing stays available, but applying a route requires disabling learned mode. An active custom route prevents enabling the model. This preserves the tested domain instead of certifying arbitrary user routes by displaying a learned card. Switching back to fixed rule use restores Route Studio. No route data or the accepted frozen training protocol is altered.

## Saved policy records
New `stone.rover.policy-session/0.1` files contain the unchanged versioned physics tape, initial/final Stone, each command's attribution, exact model/library/harness identities, terminal status and model/rule/guard counts. Every named implementation must match a reviewed first-party identity; files cannot supply a module URL. Replay recomputes the identified policy's command at each real pre-step state, checks it against the recording, and reexecutes the engine. Explicit Stop and a final selection after the last action add no physics tick. Legacy rule and route records retain their own formats and paths.

A successful policy-and-engine replay establishes reproducibility under the supplied reviewed implementation, not who produced the file, when an alleged run happened or publisher trust. A source hash is not a signature. Model loading checks the source bytes against a digest pinned by the application, not merely a user-provided checksum.

## Digital AUDIT
Field Lab / Digital / AUDIT accepts the new Rover policy recording in addition to existing manifests and route formats. Only this explicit format invokes the fixed, local verifier model, loaded from the same trusted path. It checks policy commands, actual physics and counters, returning exact file-byte SHA256 and `verification: policy-and-engine-reexecution`. `verificationModel.inferenceCalls` reports actual calls made during verification; rule-only records may load the verifier without using it. Ordinary metadata/route inspection still invokes no model. There is no report-generation model or live cloud provider.

The UI no longer states "no model invoked" for this model-aware branch. The inspected file does not install code, change endpoints, select another model or grant permissions. Wrong-host, changed-command, missing-model, malformed and oversized evidence fails without retaining successful prior output. Cancel and the worker watchdog remain independent of model completion.

## Execution and failure boundaries
The model fetch is a fixed same-origin path, credentials omitted, redirects rejected, strict UTF8, maximum64KiB including streamed bodies. Actual model bytes remain SHA256 d9a1ef32fa555b5f9d8fdd326a90b59f8c03228b3854564d99bed708d0a210c2. The application uses the original ml-cart loader/inference and shared pure policy functions, not a replacement tree interpreter. Build inventories record exact root-relative source/dependency bytes and full MIT notices; these are consistency checks, not a malware audit.

Stop terminates the worker and retains only acknowledged commands; it does not depend on a blocked worker responding. Model-loading hangs, infinite decisions, missing bundles, invalid acknowledgements and comparison/replay failures have tested recovery states. Short/empty running batches and malformed comparison envelopes are rejected before evidence is accepted. Restart marks old telemetry/rendering unavailable until a valid new state arrives. WebGL loss falls back to Plan without changing the simulation.

The core manifest exports the saved model reference. Requested memory/decision budgets remain provisional metadata, not enforced quotas or physical safety guarantees. No arbitrary third-party runtime, cloud inference, real drone/humanoid policy, physical actuation, public hosting or ClawSpan integration is included.
