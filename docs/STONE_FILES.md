# Portable Stone files

A Stone file carries the reviewed FLOW longitudinal model, a core manifest and requirements for its preinstalled adapter. It is bounded JSON data; it cannot install a runtime or grant permissions. Original STONE source and model remain UNLICENSED. Bundled dependencies retain their upstream notices.

In the locally installed Rover workbench, open **Portable Stone**. Choose [FLOW-Learned.stone.json](../examples/FLOW-Learned.stone.json), or a previously saved Stone file. Selection checks the file without resetting or moving the simulated machine. The active source stays unchanged until you select **Activate inspected Stone & reset**. Activation starts the known model context at tick zero; use the normal Start or Step controls to run it.

Only the pinned FLOW model and reviewed operating requirements are admitted. The model uses CART for longitudinal drive/brake, with deterministic steering and guards, Rapier 0.20.0, and the existing fixed lanes. Custom routes remain excluded from learned mode. Unknown models, adapters, harness versions or changed permission requirements remain unavailable. File labels, declared publisher, licence and evidence are not authenticated.

**Save FLOW Stone file** exports the actual verified parameters with the approved reference manifest. Display metadata from an imported file is not copied into that reference export. Export is available in a loaded learned context, including before running any decisions. If you have no saved file, enable the built-in learned mode first; the pinned model build and built-in weights must be available for that initial load.

A supplied source stays in the current tab for reset, inference, comparison and replay, including after Stop terminates the worker. These operations use the supplied parameter bytes even when `/models/flow-v0.1.json` is unavailable. **Use built-in model source** explicitly resets to the built-in source; a missing source fails visibly without fallback. Disabling learned mode clears the supplied source. Refresh does not retain uploads, so export a file to keep it.

Digital **AUDIT** can inspect the same file. Choose the file, select an offline compatibility target, then select **Inspect & verify file**. Package inspection reports the byte hash, artifact integrity, declared evidence and requirements without loading inference or installing anything. Policy-recording verification is a separate operation that does load the pinned verifier model. A recording binds model and implementation identities; it does not authenticate an original package or prove an event occurred.

The Rover picker accepts UTF-8 `stone.package/0.1` JSON up to 256 KiB, containing one to four JSON artifacts of at most 64 KiB each. Byte counts and SHA-256 hashes must agree. The exact UTF-8 package bytes determine the source receipt, so whitespace changes that receipt. Malformed input and failed integrity checks are rejected; consistent but unapproved data is reported as not admitted. Invalid or cancelled selection clears the inspected draft, while the active source receipt continues to identify the running or retained model context. AUDIT's general file input allows up to 2 MiB for other evidence types; portable package parsing still enforces 256 KiB.

Build the preinstalled inference bundle with `npm run build:models` using the reviewed local dependencies. No dependency or provider installation is performed by a Stone file. The complete component passed independent reduced-privilege browser and physics verification; see evidence/PORTABLE_STONES_V0_1.md. This does not establish physical-machine readiness or arbitrary-package safety.

File inputs handle both an explicit browser `cancel` event and a change to an empty selection. Explicit cancel clears the selected input and unapplied draft (or AUDIT report/source), and invalidates pending reads/inspection. It preserves Rover's active supplied model, machine state and active-source receipt. Browsers can report dismissal or same-file reselection as cancellation. Regression coverage dispatches `cancel` on native inputs with real selected files; graphical OS-dialog variants have not been automated or independently verified here.
