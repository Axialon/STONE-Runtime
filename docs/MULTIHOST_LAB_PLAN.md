# Multi-host reference expansion — delivered and remaining scope

Goal: grow interchangeable expertise beyond the preserved rover, with independent host profiles and explicit local/cloud requirements. Marketplace integration is deferred.

## Accepted increment
- [x] Thirteen experimental Lab passports across rover, drone, humanoid and digital families. Availability is independent of metadata compatibility.
- [x] Actual Rapier anchored, two-joint arm; three rule-based reaching styles; two fixed reach-and-hold tasks.
- [x] Fixed-reference benchmark API and CLI, including sampled physical poses. Not a live mutable session manager.
- [x] Digital BENCH/BRIEF tools executing the fixed benchmarks locally; no model inference claimed.
- [x] Cloud report adapter with explicit configuration/consent, bounded requests and validated output. Controlled transport fixtures only, no live provider run.
- [x] HYBRID explicit local-only fallback, visibly distinct from cloud success.
- [x] Recorded-pose rendering proof using the existing pinned Three.js and sandboxed Chrome. This is not an interactive humanoid interface.

## Not implemented by this increment
- [ ] Executable drone host and flight policies. Catalogue entries remain planned.
- [ ] Live humanoid selection/session/replay controls and combined multi-host browser interface.
- [ ] HTTP gateway for cloud execution. The accepted adapter is a Node module/CLI only.
- [ ] General uploaded-record audit and learned policies. Do not relabel fixed benchmark templates as model inference.
- [ ] Live cloud provider acceptance, multi-platform validation and physical-machine integration.

Preserve existing engine and rover limits. Reuse pinned Rapier/Three.js; no new dependencies, paid calls, global installs, automatic jobs or public application deployment. Record measured scope instead of counting stubs, blocked operations or fixtures as delivered capabilities.
