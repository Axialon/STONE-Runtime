# Interactive routes and navigation — reference acceptance evidence

## Delivered scope
A shared Route Studio drafts one to eight bounded checkpoints for Rover, Drone and the anchored humanoid arm. Nodes can be added/moved in the displayed plan, edited numerically, reordered/removed and exported/imported as bounded local JSON. Applying a route explicitly resets the run; draft changes preserve the active machine and recorded route. Each Field Lab host retains its own in-tab draft. No persistent storage or automatic upload is introduced.

Reciprocal Rover/Drone/Humanoid/Digital navigation is now present on both workbenches, in the same order, with active-page labels and Field Lab hash deep links. Direct Digital startup now correctly reaches ready state. Host refresh/Back is tested. `npm start` starts both loopback apps atomically and closes only its own servers on failure/exit; it never replaces an occupied service. Local primary destinations are fixed HTTP loopback4173/4174.

Actual existing Rapier engines consume validated custom goals without changing machine parameters, actuator limits, reference rule controllers or fixed benchmark definitions. Rover custom routes use the original flat lane and repeated original goal/stop criteria. Drone and arm preserve original distance/speed/hold criteria. Custom validity does not guarantee route completion; failures/timeouts remain possible and visible. The separate learned FLOW artifact/protocol and its fixed-task evaluation remain unchanged and are not registered for custom routes.

## Evidence semantics
Distinct custom route/session versions preserve the complete ordered route, exact host/machine/engine identities, admitted commands, action attribution, initial/final selection and terminal status. Replay reexecutes commands on that route; explicit Stop is not an extra physics tick. All custom comparisons return the full route and custom scope, and the Rover interface checks the returned route matches its applied definition. Empty-payload Rover worker comparison no longer silently selects a fixed benchmark during a custom session.

Digital AUDIT supports the three new custom-route recording formats, including Rover custom routes. It validates/reexecutes them and reports source-byte SHA256 and route-bound outcomes without installing code, calling a model/provider or authenticating an alleged original event, publisher or controller attribution. Existing core/legacy drone/arm inspection remains; unrelated recording formats are not silently converted.

## Review and limits
A fresh source-only Codex review found discarded custom comparison metadata/default-comparison ambiguity and suggested explicit fixed loopback navigation; both were addressed with regressions. Its proposed worker Stop command was not adopted: the existing UI deliberately terminates the worker to remain responsive during a blocked decision and records Stop from the last acknowledged state. The review did not include the full UI; actual all-host Stop/export/replay and existing infinite-worker tests confirm this design. Final changes received supervising self-review; no independent human/security audit is claimed.

Several large combined tool calls returned indeterminate status. No operation was treated as executed without readback. Focused transparent edits and tests using the same authorised tools succeeded; no sandbox, permission, credential or account restriction was changed. Public snapshot upload uses a reviewed static native-gh request and exact returned Git-tree equality, not manual source transcription or privileged code execution.

No new dependency graph, lifecycle script, trained-policy refit, paid inference, hosted Actions, physical-machine control, public app deployment, ClawSpan integration, expanded sharing or unrelated file change. Exact replay is tested in the recorded Linux/Node22/Chrome environment, not certified across platforms. Original private planar-suite, native mobile and a full accessibility audit remain separate. Humanoid means anchored two-joint reaching; drone physics is simplified, not flight calibration/obstacle avoidance.

## Reproduce
Use the existing pinned offline install procedures, then `npm run verify:all`, `npm run verify:learned`, `npm run verify:field`, `npm run verify:browser`, `npm run verify:learned:browser` and `npm run verify:routes`. Root `npm start` opens both primary local apps. Read docs/CUSTOM_ROUTES.md for interaction and evidence formats. The private project consumes only the accepted runtime commit, never an unverified draft.
