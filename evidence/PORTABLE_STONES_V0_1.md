# Portable Stone files 0.1 — accepted verification evidence

## Actual capability
A local JSON file carries the reviewed FLOW model, core manifest and known preinstalled adapter requirement. Rover inspects it without moving the machine, explicitly activates it at tick zero, then uses its exact supplied weights for decisions, comparisons and replay, including after worker termination. These operations were tested while the server's separate model-weight path was unavailable. Digital AUDIT inspects package metadata and byte integrity without loading the model or invoking inference.

This is not an executable-code installer or arbitrary-model loader. Only the existing reviewed FLOW artifact and exact admitted operating requirements can activate. Model/library/harness identity remains trusted runtime data rather than an imported label. Unknown-but-consistent data is not admitted; malformed or integrity-invalid data is rejected. Publisher, licence and evidence statements remain declarations, not authenticated claims. Uploaded data is tab-local; export is explicit. Existing route editor, all-host navigation, legacy rules and live learned fixed-lane scope are preserved.

`stone.package/0.1` is bounded to256KiB,1–4 JSON artifacts of at most64KiB each. Raw artifact byte counts and SHA256 must agree. The shipped example is generated only from the reviewed model and reference manifest. Model SHA256 d9a1ef32fa555b5f9d8fdd326a90b59f8c03228b3854564d99bed708d0a210c2 and frozen training protocol ee6f721ca0cd79788efb0023f89a322913181703b5ddb56ab33bbe56bbe978e1 did not change. No retraining, test tuning, dependency addition or broader model evaluation occurred.

Browser tests dispatch cancel on native input elements holding actual files, including delayed-read cases; graphical operating-system file dialogs and browser-specific dismissal variants were not automated.

## Review and execution limits
Native Codex implemented directly in its dedicated checkout under the ordinary workspace sandbox, not merely as a source-only proposal. The first bounded run reached its time limit; an exact-session continuation produced the handoff. Its narrow direct tests are supporting evidence, not a substitute for independent acceptance. Native .git writes were denied and left protected; the supervisor handles authorised integration. Subprocess/file-level-test and WASM limitations in the native environment were disclosed, not bypassed.

The supervising runner independently installed and executed the entire component under reduced privileges with the browser sandbox retained. Linux x64, Node22.20.0, Rapier0.20.0 and the existing Chrome installation were exercised. The source-only review is a real separate model session, not an independent human/security audit. Other browser engines, native-mobile devices, legacy private planar suite, comprehensive accessibility, general navigation and physical-machine safety remain outside this verification.

The complete reviewed source and raw-run hashes were checked before integration; final snapshot.json identifies selected source bytes. Generated model bundles are rebuilt rather than included as executable uploads. Package checksums prove consistency/identity, not authorisation or publisher signatures. Source/model remain UNLICENSED and upstream terms are unchanged.

No paid API inference, credit purchase, hosted Actions retry, public app deployment, physical-machine operation, credential transfer, sandbox/trust weakening or ClawSpan/NPCA-Z change. The next capability must use the same explicit admission principles rather than adding a hidden arbitrary-code path.
