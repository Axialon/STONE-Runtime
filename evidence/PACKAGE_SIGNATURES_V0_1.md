# TRUST001 — detached package signatures, not publisher enrollment

## Delivered scope
A shared standard-WebCrypto Ed25519 implementation verifies a bounded detached signature over the exact original Stone package bytes. The versioned STONE domain prefix ends with LF and is prepended before signing; it is PureEd25519, not Ed25519ctx/prehash or a standardized envelope claim. SHA256 identifies package bytes and raw public keys. The original package parser remains authoritative; signature verification never alters executable admission or existing FLOW/data-adapter restrictions.

The optional Digital panel accepts two public files and an optional independently obtained expected-key fingerprint. Verification is explicit, in an owned module worker, with deadline/Stop/input-change/native-cancel/host-leave/pagehide invalidation. No automatic verification or stored key/trust setting. Reports separately identify signature validity, key fingerprint equality, publisherIdentity:not-established, installation:not-performed and executionAdmission:unchanged. No green trusted-publisher badge or implicit authority. Correctly signed unknown runtimes remain unavailable under the preexisting admission policy.

The separate Node CLI can sign with an explicitly supplied unencrypted Ed25519 PKCS8 PEM on stdin only; it never discovers, generates or persists deployment keys, accepts private-key command arguments/environment values, overwrites files or contacts providers. It derives public keys with Node's standard crypto and signs/verifies with the shared WebCrypto boundary. Public envelopes/reports go to stdout; bounded input and output errors produce sanitized diagnostics. Mutable intermediate key buffers are cleared where possible, not a guarantee of complete JavaScript/internal memory erasure. Pipe output is not atomic and may be partial on failure.

## Bounds and formats
Package<=256KiB and existing manifest/artifact validation; envelope<=8KiB, exact five fields, Ed25519 only, SHA256 lower-case hex, canonical padded base64 raw32-byte public key and64-byte signature. Strict UTF8 and duplicate/unknown envelope field rejection. Optional expected hex fingerprint trims/lowercases only its own value; original package bytes are never canonicalized. Newlines, whitespace and Unicode changes invalidate the signature even if parsed package semantics appear similar. Private PEM stdin<=16KiB/10seconds; file inputs require bounded regular files; input paths and key contents are not echoed on errors.

## Continuation boundary
This completes cryptographic consistency/key-match evidence only. Actual publisher identity, ownership of deployment keys, trusted-key enrollment, distribution/rotation/revocation and any authority to execute newly admitted code remain separate owner-approved policy. A matching fingerprint is useful only to the extent the operator obtained it independently; the software does not establish that provenance. Live provider credentials/data transfer/spending and ClawSpan remain separately gated. No new dependency/model training/controller/physics change, paid inference, account/security change, public application deployment, physical operation or sibling repository edit.

Usage and standard primary references are in docs/PACKAGE_SIGNATURES.md. Native implementation receipt is pre-acceptance evidence, not current release status. Other browsers/devices, graphical OS-dialog variants, private legacy tests and broad security certification remain unverified. Rollback is a scoped runtime revert and private component pin rollback.
