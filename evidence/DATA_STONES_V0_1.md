# D001 — Data Stones and a reusable local authoring path

## User-visible delivery
LENS and TIDY are actual portable declarative Digital Stones for user CSV/JSON tables, not simulator reports. They execute through one preinstalled data-quality adapter and the existing stone.package/0.1/core-manifest contracts. A user-authored third configuration can be prepared, inspected, exported, reimported, explicitly activated and run through that same adapter without adding a central package-name branch. Runtime/privileges remain reviewed and fixed; names, IDs, publisher and evidence are declarations, not authenticated identities.

LENS exposes complete row/column/missing/duplicate/header/whitespace/mixed-shape/formula-like counts and bounded findings. TIDY proposes string edge trimming and optional removal of entirely empty rows. Original bytes and leading-zero identifiers remain intact. Duplicate rows/headers are not silently rewritten. Before/after changes, exact source/package/adapter receipts and explicit new JSON downloads are available. These packages are deterministic tools: model:null, actualExecution:local. They are not neural models, semantic truth checkers or domain-specific decisions.

The small authoring form uses only allowlisted check names and boolean transforms. Creation is metadata inspection, not activation or dataset execution. Prepared and active packages have different export controls. Editing a draft invalidates its admission receipt without changing the active report; activation clears prior results and selects the exact prepared configuration. Stop/host leave/disposal terminate and invalidate both preparation and processing; interrupted setup requires explicit retry, never restarting off-host.

## Data and output limits
UTF-8 input <=1MiB, <=5000 data rows, <=64 columns, <=8192 characters/cell. CSV uses actual Papa Parse5.5.3 with header:false/dynamicTyping:false, preserving quoted commas/newlines and duplicate headers. Flat JSON records/scalar rows or the documented grid are accepted; nested/nonfinite/unsafe integer values are rejected. JSON numeric spelling and duplicate object keys are not preserved by parsing; original source bytes are not overwritten. Display limits100 findings/examples,20rows/8columns/160characters per preview cell are labelled and do not truncate admitted input.

Normalized output is an exact compact stone.data-grid/0.1 file that reimports through the JSON path. Separate proposal evidence carries the receipt and undo operations. If serialized grid bytes exceed the same1MiB limit, grid export is withheld with explanation; complete counts/report and the original remain. This corrected a concrete640127-byte CSV whose grid exceeded1.29MiB. No CSV formula-safety claim: formula-like strings remain inert JSON/text. Undo restores the parsed grid, not the original CSV lexical encoding.
